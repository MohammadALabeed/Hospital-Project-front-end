# MedCenter Pro
## واجهة نظام المجلس الطبي الذكي متعدد الوكلاء

واجهة أمامية لإدارة بيانات المرضى والمواعيد والسجلات الطبية، مع ربط خدمات النظام بواجهة برمجية خلفية، وعرض نتائج المجلس الطبي الذكي وأرشيف استشاراته.

## المزايا

- **لوحة التحكم (`Overview`)**: تعرض إحصائيات المرضى والموظفين والأطباء التي يجلبها التطبيق من الخادم، مع مؤشر تحميل أثناء استرجاعها.
- **إدارة المرضى (`Patients`)**: استعراض سجلات المرضى وأسمائهم وأرقامهم، وتحديث فصيلة الدم. يظهر زر حذف السجل للمدير فقط.
- **المواعيد (`Appointments`)**: إنشاء المواعيد باستخدام قوائم المرضى والأطباء، وعرض الأسماء والحالات وتحديثها. الحذف متاح للمدير فقط.
- **السجلات الطبية والمجلس الذكي (`MedicalRecords`)**: إنشاء السجلات ومراجعتها، وطلب تحليل المجلس الطبي وعرض توصيته النهائية والفحوصات المقترحة.
- **الوصفات الطبية (`Prescriptions`)**: من السجل الطبي يمكن عرض الوصفات المرتبطة به وإضافة وصفة جديدة تتضمن اسم الدواء والجرعة وملاحظات اختيارية.
- **أرشيف الاستشارات**: لكل سجل طبي قائمة بالاستشارات السابقة مرتبة بالتاريخ. يمكن فتح أي تقرير قديم وعرض تفاصيله للقراءة فقط.
- **بطاقات وكلاء المجلس**: تعرض التحليل التشخيصي، وتحذيرات سلامة الأدوية والتداخلات، وملخص التوافق. تظهر تحذيرات الأدوية بوضوح، وتكون شارة التوافق خضراء عند بلوغ 80% أو أكثر، وتحذيرية عند انخفاضها.

## الصلاحيات

تستخدم الواجهة دور المستخدم المحفوظ ضمن جلسة تسجيل الدخول (`RoleID`) لإظهار الخيارات المناسبة:

| الدور | الصلاحيات الظاهرة في الواجهة |
| --- | --- |
| `Admin` | إدارة الواجهة، بما في ذلك أزرار حذف المرضى والمواعيد، والوصول إلى الوصفات الطبية. |
| `Doctor` | استخدام الواجهات الطبية والوصفات، دون إظهار أزرار حذف المرضى أو المواعيد. |

إخفاء الأزرار في الواجهة ليس بديلاً عن التحقق الأمني؛ يجب أن يظل الخادم مسؤولاً عن المصادقة والتفويض والتحقق من صلاحية كل طلب.

## التقنيات

- **React 19** لبناء واجهة قائمة على المكونات.
- **TypeScript** لتعريف أنواع البيانات والجلسات والأدوار.
- **Vite** لتشغيل خادم التطوير وبناء التطبيق.
- **Tailwind CSS 4** لتنسيق الواجهات.
- **Axios** للاتصال بالـ API عبر عميل موحّد في `src/api.ts`، مع `withCredentials: true` لإرسال كوكيز الجلسة.
- **i18next وreact-i18next** للترجمة الفورية بين العربية والإنجليزية. تضبط الواجهة اتجاه `RTL` أو `LTR` بحسب اللغة، وتستخدم `dir="auto"` للنصوص الديناميكية المختلطة.
- **Lucide React** للأيقونات.

## متطلبات الاتصال بالباك إند

يستخدم عميل API العنوان المحدد في متغير البيئة `VITE_API_URL`، وعنوانه الافتراضي `http://localhost:3000`. لتحديد عنوان مختلف، أنشئ ملف `.env.local` في جذر المشروع:

```env
VITE_API_URL=http://localhost:3000
```

شغّل الباك إند أولاً، وتأكد من إعداد CORS للسماح بأصل واجهة التطوير وبيانات الاعتماد (`credentials`) عند استخدام كوكيز الجلسة. أعد تشغيل Vite بعد تغيير متغيرات البيئة.

## التثبيت والتشغيل المحلي

يتطلب المشروع Node.js وnpm.

```bash
npm install
npm run dev
```

افتح العنوان الذي يعرضه Vite، ويكون افتراضياً:

```text
http://localhost:5173
```

لإجراء فحص TypeScript:

```bash
npm run lint
```

## بنية `src/`

```text
src/
├── components/
│   ├── Appointments.tsx
│   ├── Layout.tsx
│   ├── Login.tsx
│   ├── MedicalRecords.tsx
│   ├── Overview.tsx
│   ├── PatientModal.tsx
│   └── Patients.tsx
├── locales/
│   ├── ar.json
│   └── en.json
├── api.ts
├── App.tsx
├── i18n.ts
├── index.css
├── main.tsx
├── personDirectory.ts
└── types.ts
```

- `components/`: صفحات النظام ومكونات التخطيط والنماذج.
- `locales/`: موارد النصوص العربية والإنجليزية التي تستخدمها `react-i18next`.
- `api.ts`: إعداد عميل Axios وعنوان API وبيانات اعتماد الجلسة.
- `App.tsx`: تدفق الجلسة وتسجيل الدخول والتنقل بين الصفحات.
- `personDirectory.ts`: تحليل بيانات المرضى والأطباء لبناء خيارات القوائم المنسدلة وعرض الأسماء.
- `types.ts`: أنواع بيانات المستخدم والجلسة والأدوار وسجلات المرضى.
- `i18n.ts`: تهيئة اللغات وتحديث لغة واتجاه مستند الصفحة.
